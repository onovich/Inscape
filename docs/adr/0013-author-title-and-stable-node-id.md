# 0013：作者标题与稳定节点 ID 分离

状态：Accepted

## 背景

`:: node.name` 适合程序实现，但写作者更自然的块标题是 `# 中文标题`。如果直接把中文标题作为长期机器 ID，标题重命名、本地化锚点、外部引用和存档迁移都会变脆；如果强迫作者手写机器 ID，又会破坏写作体验。

项目需要同时满足两个目标：

- 作者在脚本里主要看到、输入和跳转中文标题。
- 程序内部拥有稳定、不随标题文案轻易变化的节点身份。

## 决定

第一版块语法的长期方向改为 `# 标题`。标题是作者界面的主身份，必须在同一 Inscape project 内唯一。

程序层不把标题本身当作长期稳定 ID。节点应拥有系统维护的 stable node id；标题与 stable node id 自动关联。未来可以通过 sidecar 索引、迁移表或必要时显式 `@id` 记录该关联，但默认写作体验不要求作者手写机器 ID。

空行不参与节点边界判断。`# 标题` 本身结束上一个节点并开始新节点。标题前缺少空行时，工具可以给 style warning 或 info，提醒作者为了可读性建议空一行，但不应作为编译错误。

自动创建新节点时，如果标题已存在，编辑器或创建命令应生成唯一标题，例如：

```inscape
# 法庭开场

# 法庭开场_01
```

编号格式使用 `_01`、`_02` 起步，超过两位自然扩展为 `_100`。

如果用户手动把标题改成项目内已有标题，Compiler / LanguageServer 应给 duplicate title diagnostic，而不是静默改写用户文本。

## 原因

- `# 中文标题` 更接近写作者的自然组织方式，也更适合大纲、预览和未来节点图显示。
- 项目级标题唯一让跳转、补全和引用展示保持直觉，不需要作者在同名标题之间做隐藏消歧。
- stable node id 独立存在，可以支撑标题重命名、本地化锚点迁移、外部引用和存档兼容。
- 自动编号只在创建动作中发生，避免普通文本编辑被工具偷偷改写。
- 空行作为版式建议而不是语义要求，可以减少非本质错误，同时保持编辑器有机会提示可读性问题。

## 影响

- `:: node.name` 需要进入兼容 / 迁移路径；新推荐写法应改为 `# 标题`。
- Parser 需要支持 `# 标题` 节点声明，并校验项目级标题唯一。
- 跳转语法需要从机器式 node name 迁到作者标题引用，内部解析到 stable node id。
- VSCode / LanguageServer 需要补标题补全、重复标题诊断、创建新节点自动 `_01` 编号，以及标题前缺少空行的 style hint。
- 本地化、预览、Runtime 和 ExternalSupport 输出应逐步区分 display title 与 stable node id。
- 节点重命名迁移策略应基于 stable node id，而不是把标题文本变化直接视为新节点。

## 后续验证

- 增加 parser / project compiler 测试：中文标题、跨文件重复标题、标题重命名、标题前无空行、空节点。
- 增加 VSCode 回归：新建同名标题自动生成 `_01`，手动重名显示 diagnostic，outline / completion 显示中文标题。
- 增加本地化回归：标题改名后，行级锚点迁移应优先通过 stable node id 保持继承。
