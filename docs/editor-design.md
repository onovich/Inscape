# 编辑器设计草案

状态：基线 + 草案，交互未定稿

## 产品定位

Inscape 编辑器是叙事创作者和开发者共享的独立工作台。它不只是文本编辑器，也不是一开始就复杂化为完整节点图系统。第一阶段应该围绕脚本文本、诊断、大纲、预览和状态观察建立高效闭环。

正式独立编辑器属于第三步，但 DSL 阶段就需要提供轻量工具链：VSCode 语言支持和 HTML 调试预览。它们不是最终产品形态，而是帮助语言设计快速反馈的工作台。

自研编辑器的当前架构定位见 [自研编辑器架构方案](self-hosted-editor-architecture-plan.md) 与 [ADR 0017](adr/0017-self-hosted-editor-external-support-boundary.md)。简要结论是：自研编辑器作为第一方宿主客户端落在 `src/ExternalSupport/SelfHostedEditor`，语义、工具流程、语言服务和运行期能力继续复用 `Internal` 的 `Compiler`、`Tooling`、`LanguageServer` 与 `Runtime`。

体验上不应只参考 Inky。当前判断是：Inky 的“边写边玩”值得借鉴，但整体编辑器体验没有充分利用现代编辑器能力。Inscape 后续应更多参考三类对象的结合：

- 编程编辑器的可导航性、补全、诊断、定义/引用跳转和项目级检索。
- Notion / Medium 的低干扰写作感、结构感和视觉层次。
- 叙事工具的图视图、预览和本地化上下文。

## DSL 阶段 VSCode 支持

第一阶段需要尽量降低用户记忆负担，代码提示不是锦上添花，而是 DSL 可用性的核心部分。

目标能力：

- TextMate 语法高亮：弱化节点元信息、注释、跳转符号和标签，凸显剧情文本、角色名和选项文本。
- 语义高亮：区分节点定义、节点引用、角色、对白、旁白、选项、元信息和诊断区域。
- 自动补全：节点名、角色名、资源别名、选项模板、跳转目标和未来的查询谓词。
- 跳转定义：从 `-> node.name` 跳到节点定义。
- 引用查找：查看某个节点被哪些选项或跳转引用。
- 诊断：重复节点、缺失目标、不可达节点、疑似死循环、孤立节点、空选项、未闭合块、重复角色别名。
- 悬浮说明：解释节点、锚点、补全项和宿主 Schema。
- 大纲视图：按文件显示节点、选项和跳转。
- 点击预览跳转代码：后续需要支持从预览中的行、角色、事件、节点直接回到代码面板对应位置。

## DSL 阶段 HTML 调试预览

第一阶段后期需要提供类似 Inky 的轻量 HTML 预览。

目标能力：

- 从编译产物读取 Narrative Graph IR。
- 显示当前节点的对白、旁白和选项。
- 点击选项进入目标节点，允许回环。
- 显示当前节点名、行级 hash、本地化 key 和诊断信息。
- 提供返回、重开、路径记录和简单搜索。
- 支持通过项目级 CLI `--entry node.name` 从任意节点临时启动预览。
- 不追求演出美观，不模拟 Unity Timeline，不加载复杂素材。

当前 CLI 已经支持单文件/项目级静态 HTML 预览。VSCode WebView 预览尚未接入，建议后续复用 CLI 生成的项目级 IR 与 `Inscape.Tooling` 内现有的预览渲染逻辑。

## DSL 阶段本地化工具

当前 CLI 已经支持：

- `extract-l10n` / `extract-l10n-project`：导出当前可翻译文本。
- `update-l10n` / `update-l10n-project`：读取旧 CSV，按 `anchor` 精确继承译文，并标记 `current/new/removed`。

当前 VSCode 原型已提供命令面板入口，使作者不用离开编辑器即可导出或更新翻译表：

- `Inscape: Export Localization CSV`
- `Inscape: Update Localization CSV From Previous Table`

如果当前 `.inscape` 文件未保存，命令会通过 CLI `--override` 使用编辑器中的临时内容。

模糊匹配与人工确认 UI 后续再设计。

本地化工具与宿主配置工具应分开：翻译 CSV、角色/资源绑定 CSV、宿主事件清单都可能是 CSV，但它们不是同一种界面模型，也不应在概念上混用。

## 自研编辑器编辑体验

自研编辑器的脚本工作台默认采用类似主流 Markdown 编辑器和 VSCode 预览的双栏体验：左栏是 `.inscape` 脚本文本编辑器，右栏是效果 / 运行预览。双栏可以随时切成单栏，进入仅编写或仅预览模式。预览不是装饰面板，而是写作闭环的一半；点击预览中的文本、选项、节点、诊断或本地化项，应能定位回左栏源位置，左栏光标和选择变化也应能驱动右栏轻量跟随。

编辑器与运行时的基本对象应是“项目工作区”而不是“单个脚本文件”。也即：只要 `.inscape` 文件位于同一项目目录下，它们就应共享同一个 workspace 上下文、同一份 LanguageServer / Tooling / Runtime 语义视图，并支持跨文件定义、引用、跳转和节点目标解析。这条约束应当像 C# 项目对待多文件代码那样被视为默认前提，而不是后续补丁能力。

书写和阅读体验对标 Notion，而不是传统 IDE 的高密度配置界面。正文应有稳定留白、清晰段落层次和轻量结构提示；元信息、状态、行号、锚点和候选提示默认退到视觉背景中，只有当用户悬停、聚焦、选择或执行操作时才增强。目标是让作者在大部分时间里感觉自己是在写一篇干净的叙事文稿，而不是在维护一张复杂配置表。

在默认状态下，主写作视图要更接近 “Inky 的双栏骨架 + Notion 的正文优先层级”，而不是 IDE 里多面板同时常亮的工作台。当前判断是：编辑器与预览是主舞台；大纲、session 状态、诊断和其他辅助信息应该像安静的边缘层，默认轻、薄、淡，只有 hover、focus 或明确切换到对应视图时才增强存在感。

Monaco Editor 是 VSCode 编辑器核心的开源网页版本。它适合用作自研编辑器的文本编辑区，因为它天然支持语法高亮、诊断标记、补全、Hover、跳转、引用、快捷键和装饰层。Inscape 自研编辑器使用 Monaco 的目的不是“看起来像代码编辑器”，而是尽量继承 VSCode 级别的编辑体验，同时把语义来源继续保持在 `LanguageServer` / `Tooling` / `Compiler`。

自研编辑器必须把 VSCode 中已有的作者体验作为最低基线：跳转定义、引用查找、补全、Hover、错误提示、诊断列表和语义级重命名，都应在独立编辑器中获得等价能力。无法在第一版实现的能力需要显式列入缺口，而不是隐式降级。

编辑器视觉分为两层：

- 文本层：正文、角色、选项等主要阅读和写作内容，保持清晰、稳定、低干扰，并优先服务 Notion 式的连续阅读和块级写作体验。
- 提示层：节点身份、跳转目标、anchor、line id、line fingerprint、本地化状态、候选译文、诊断辅助和其他元信息，默认更小字号、更低对比度、淡灰色显示；只有在 hover、focus、selection 或可交互状态下才增强高亮。

这意味着提示信息应像“贴在文本旁边的安静注解”，而不是抢正文视觉权重的标签墙。可交互提示需要在 hover 时清楚表达可点击性，但常态下不应破坏阅读节奏。

当前已经明确的具体交互要求如下，后续实现与评审都应以此为准：

- 单词级选择不应默认形成重灰色整词块。选区高亮应尽量轻，避免像“贴了一块胶带”那样打断阅读；如果只是为了导航、Hover 或可点击性，也不应额外制造冗余词块背景。
- 行号默认不显示；只有鼠标悬停或光标选中某一正文行时，才显示该行的完整块内行号。悬停任意 block 或正文时不应批量显示全部行号。
- 行号是 block 内概念，标题行不显示行号；每个 block 内的正文、prompt、choice、jump 等可编辑内容从 `1` 独立计数。
- 稳定身份是全局概念，不能和连续 source line 混用。正文行的稳定 line id 来自 localization line sidecar。标题的 stable node id 属于内部语义与维护流程，不应在默认写作表面暴露；标题左侧只保留引用计数、新增 block 与拖拽把手等操作入口。
- 当用户悬停块内行号时，完整 stable line id 在行号左侧显示，右对齐并向左延展，不改变正文排版。SelfHostedEditor 在真正接入 sidecar 前只能显示“id not loaded”一类占位状态，不能伪造稳定 id。
- 标题、正文、旁白、prompt、选项应有可感知但克制的层级差异；当前倾向是通过字重、斜体和颜色深浅区分，而不是靠过多标签。
- 当光标或选择位于标题 block 时，可以出现整个 block 的浅背景高亮；这类高亮应参考 Notion，存在感轻，目的是表达“你正在操作这个 block”，而不是把正文洗成卡片。
- 引用 / 跳转候选列表不应像 Monaco 默认 peek 那样插入并撑开原有排版。长期目标是浮层式候选面板：直接覆盖在正文之上，不改变文稿流。
- 第一版 SelfHostedEditor 已开始按这个方向推进：标题左侧引用计数按钮与 `Shift+F12` 都应优先走自定义 references overlay，而不是 inline peek。
- block 标题 hover 时，左侧应出现两个 Notion 风格图标：一个用于在下方新增 block，一个用于拖拽重排 block 顺序。拖拽重排默认只改变文本中的 block 排列，不应隐式修改逻辑跳转关系。
- 节点图视图长期参考 Yarn Spinner：图中可以直接修改跳转关系、拖拽节点画布位置，并与文本视图保持双向导航；但“节点位置”是展示元数据，不是逻辑语义。
- 项目对象长期必须是 workspace，而不是单文件。多 `.inscape` 文件共享上下文、跨文件引用和跳转，是编辑器与语言服务的默认前提。
- 第一版 workspace 壳已接入目录 / 多文件导入入口：可以一次导入同目录多份 `.inscape`，并保留 workspace 名称、文件数和相对路径状态；真正的跨文件语义解析仍是后续阶段目标。
- 当前第二步已明确：workspace 级 `LanguageServer` 查询要优先覆盖 diagnostics、completion、definition、references、hover 这些高频编辑动作。开发宿主可先通过临时 workspace + project probe 供给语义，但正式桌面宿主仍应收敛到稳定的长会话桥，而不是长期停留在“每次查询临时拼工作区”的形态。
- references / jump 候选浮层除了“不撑开正文”之外，还要支持跨文件来源显示与跨文件跳转；候选标签应优先显示相对路径 + 行号，而不是只显示行号或只显示标题。

当前还应明确一条界面纪律：任何辅助信息如果不能帮助用户在两秒内继续阅读或继续写作，就不应默认常驻在主视图中央区域。Problems、Localization、Node Graph 和会话状态都属于可切换或边缘层，而不是首页主构图的一部分。

## 目标工作流

1. 作者打开项目和脚本文件。
2. 第一阶段在 VSCode 中编写 DSL，第三阶段迁移到 Monaco Editor 独立编辑器；独立编辑器默认左栏编辑、右栏预览，并可切换为仅编写或仅预览。
3. 编辑器实时解析或增量解析，展示错误、警告和大纲。
4. 保存后生成 IR、本地化提取表和热重载 Patch。
5. Unity 预览窗口接收 Patch，刷新可安全更新的指令堆栈。
6. 作者通过变量监视器和时间回放检查分支效果。

## 多视图原则

后续独立编辑器默认应围绕四类主视图组织：

- 编辑器视图：主视图，负责 Notion 式写作 / 阅读、诊断、补全、跳转、引用和语义级重命名。
- 预览视图：运行 / 效果视图，负责验证分支、选项、路径和当前运行状态。
- 本地化编辑视图：生产视图，负责本地化 CSV、alignment review、候选译文、状态筛选和源位置跳转。
- 节点图视图：结构视图，负责理解和预览节点连接；后续也应支持受控编辑，但不能成为独立漂移的第二份真相。

节点图视图的长期方向应参考 Yarn Spinner Graph View：既能显示类似思维导图的节点与边，也允许作者直接在图中修改跳转关系，并通过拖拽调整节点在画布中的视觉位置。需要注意的是，图中的“位置”应被视为纯展示元数据，不应改变文本里的逻辑跳转真相；而图中边的编辑必须通过明确 command / patch 回写源文本或 sidecar。

这些视图都应基于同一份 IR / 中间表数据工作，而不是各自维护一套彼此漂移的状态。节点图编辑如果落地，应通过明确 command / patch 回写文本源或 sidecar。

默认主视图中的 block 交互也应参考 Notion：标题 block 在 hover 时，左侧出现轻量的“新增下方 block”入口与“拖拽把手”入口；前者用于在当前 block 下插入新 block，后者用于调整 block 在全文中的显示顺序。这里的“顺序”默认只改变文本中的 block 排列或相应 sidecar 中的展示位置信息，不应隐式改写 jump 逻辑本身。

## 第一阶段界面候选

- 文件树：浏览脚本、角色、资源和本地化表。
- 编辑区：Monaco Editor，支持语法高亮、错误下划线、补全、悬浮说明、跳转、引用和语义级重命名。
- 双栏预览区：默认右栏显示运行 / 效果预览，支持从预览跳回源文本，也支持跟随左栏光标；布局可切换为仅编写或仅预览。
- 大纲区：显示章节、节点、选择、跳转和角色出场。
- 诊断区：显示编译错误、资源缺失、未使用变量和本地化异常。
- 预览连接状态：显示 Unity 或未来运行时是否在线。

## 第二阶段界面候选

- 多视图切换：编辑器视图、预览视图、本地化编辑视图、节点图视图。
- 逻辑图：从文本结构生成可视化分支图；后续允许受控编辑，但编辑结果必须回写文本源或稳定 sidecar。
- CSV 视图：支持按行/列选择、多选编辑、删除、剪切、智能填充与点击跳转源文本。
- 状态监视器：显示变量、标志位、当前锚点和执行历史。
- 时间回放：基于 Action 历史跳回任意剧本节点。
- 本地化面板：查看文本、译文、修改状态和疑似继承建议。
- 资源引用面板：检查背景、立绘、音频等引用是否存在。

## 交互待确认

- 编辑器的主交互是纯文本优先，还是文本 + 图双主视图。
- 双栏布局在窄屏、单屏和多窗口下的折叠规则。
- 逻辑图第一版只做预览还是提前建立可编辑 patch contract；长期需要支持可编辑节点图，但不能破坏文本源主真相。
- 节点图如何表达条件边、回环、多重引用和“返回上一层”这类双向导航需求。
- CSV 视图只做本地化，还是也承载部分配置编辑；当前倾向是分开。
- 实时解析是按键级、保存级，还是防抖后的增量解析。
- 热重载失败时的体验是什么：回滚、提示重启预览，还是局部禁用。
- 变量监视器是否允许直接编辑运行时变量。
- 时间回放如何处理随机数、异步资源加载和外部系统副作用。

## 技术待验证

- Tauri 后端监听文件变更与项目索引的性能。
- Windows 与 macOS 的安装包、签名、自动更新、文件权限和 LanguageServer 进程管理。
- iOS / Android 未来支持的可行性与限制；当前仅保留低优先级架构余量，不进入第一版研发目标。
- Monaco 自定义语言服务的诊断、补全和语义标记能力。
- WebSocket Patch 协议是否足够，是否需要 Socket.io 的重连和事件语义。
- Unity 预览端热重载最小协议。
- 大型剧本项目的索引、搜索和跨文件跳转性能。
